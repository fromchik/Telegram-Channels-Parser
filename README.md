# Telegram Parser Bot

Telegram Parser Bot помогает собирать публикации из Telegram-каналов, обрабатывать их с помощью ИИ и публиковать готовые материалы в целевой канал. Проект ориентирован на контент-команды, администраторов каналов и специалистов, которым нужно быстро отсматривать источники, сохранять структуру постов и готовить материалы к повторной публикации.

## Возможности

- Добавление Telegram-каналов по username, публичной ссылке или invite-ссылке.
- Группировка источников в коллекции для удобного парсинга по темам или клиентским направлениям.
- Запуск парсинга одного канала, отдельной коллекции или всех подключенных источников.
- Настройка лимита постов и периода поиска перед запуском.
- Получение текста поста вместе с фото или видео, если медиа есть в исходной публикации.
- Защита от дублей: уже обработанные публикации сохраняются в базе.
- ИИ-обработка постов через OpenRouter: перевод на русский, очистка от водяных знаков и аккуратное перефразирование.
- Публикация обработанного поста в целевой Telegram-канал без метки пересланного сообщения.
- Owner-only доступ через список разрешенных Telegram user id.
- Поддержка Docker Compose, миграций Alembic и автоматизированных тестов.

## Пользовательский сценарий

1. Владелец бота добавляет нужные Telegram-каналы.
2. Источники можно объединить в коллекции, например по нишам, клиентам или языкам.
3. Перед парсингом выбирается период и количество постов.
4. Бот присылает найденные публикации в удобном Telegram-формате.
5. Пользователь может обработать пост через ИИ и сразу опубликовать результат в свой канал.

## Архитектура

Проект разделен на независимые слои:

- `app/domain`: бизнес-сущности, исключения и интерфейсы.
- `app/application`: сценарии использования, DTO, авторизация и прикладные сервисы.
- `app/infrastructure`: база данных, конфигурация, логирование, Telethon gateway, OpenRouter client и DI container.
- `app/presentation`: Telegram handlers, callback data, клавиатуры, состояния и пользовательские сообщения.

Такой подход отделяет бизнес-логику от Telegram-интерфейса и упрощает развитие проекта: можно менять UI, базу данных или внешние интеграции без переписывания ядра приложения.

## Работа с Telegram

Для чтения истории каналов используется пользовательский Telegram-клиент через `Telethon`, потому что Bot API не дает полноценного доступа к истории произвольных каналов.

Практические условия:

- для публичных каналов обычно достаточно валидной Telethon session;
- для приватных каналов session должна принадлежать аккаунту, который уже имеет доступ к этим каналам;
- session можно один раз создать локально и использовать дальше без повторной авторизации;
- при ошибке `AuthKeyUnregisteredError` нужно пересоздать Telethon session.

## Конфигурация

Создай локальный `.env` из шаблона:

```bash
cp .env.example .env
```

Основные переменные:

- `BOT_TOKEN`: токен Telegram-бота.
- `BOT_OWNER_IDS`: список разрешенных Telegram user id через запятую.
- `DATABASE_URL`: строка подключения SQLAlchemy async.
- `TELEGRAM_API_ID`: Telegram api_id.
- `TELEGRAM_API_HASH`: Telegram api_hash.
- `TELETHON_SESSION_STRING`: Telethon session в строковом формате, если используется этот способ хранения.
- `TELETHON_SESSION_FILE`: путь к локальному session-файлу.
- `MEDIA_STORAGE_DIR`: папка для временного хранения скачанных медиа.
- `OPENROUTER_API_KEY`: API-ключ OpenRouter для ИИ-обработки.
- `OPENROUTER_MODEL`: модель OpenRouter.
- `OPENROUTER_BASE_URL`: base URL OpenRouter API.
- `PUBLISH_CHANNEL_ID`: username или id канала для публикации готовых постов.

## Локальный запуск

Установить зависимости:

```bash
pip install -e .[dev]
```

Применить миграции:

```bash
alembic upgrade head
```

Один раз создать Telethon session:

```bash
python -m app.scripts.generate_telethon_session
```

Запустить бота:

```bash
python -m app.main
```

## Запуск через Docker Compose

```bash
docker compose up --build
```

## Тесты

```bash
pytest
```

## Безопасность данных

В репозиторий не добавляются локальные секреты и runtime-данные:

- `.env`
- Telethon session-файлы (`*.session`)
- локальная SQLite база (`data/*.db`)
- скачанные медиа (`data/media/`)
- Python-кэши и build artifacts

Для публичной демонстрации используется `.env.example`, где нет реальных ключей и токенов.

## Ограничения и развитие

Текущая реализация поддерживает одиночные фото и видео в публикациях. Для дальнейшего развития можно добавить полноценную поддержку альбомов, расписание автопарсинга, расширенные фильтры по ключевым словам и более гибкие роли для командной работы.

## Юридические и технические замечания

- Используйте проект с учетом правил Telegram и прав на контент.
- Не подключайте приватные источники без разрешения владельцев.
- При массовом парсинге нужно учитывать `FloodWait` и лимиты Telegram.
